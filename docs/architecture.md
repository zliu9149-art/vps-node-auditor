# 实际环境优先的接入架构

## 开发顺序

项目不再把完整本地模拟作为真实接口开发的前置门槛。正式接入顺序为：

```text
实际 VPS 严格只读审计
        ↓
确认 sing-box/Xray 版本、构建能力和 Stats 输出
        ↓
实现真实 StatsSource 与 Linux 系统指标源
        ↓
前台单次只读试采集
        ↓
单一 SQLite audit.db
        ↓
node-audit top/user/incident/month/health
```

只读审计不安装软件、不修改配置、不重载或重启服务。常驻部署仍必须在审计报告、实施命令、权限和回滚方法明确后单独获得批准。

## 当前代码基础

当前代码已经提供：

- 单一 SQLite 模型及只读查询接口；
- 累计计数器首次基线、正常增量、确认重启、异常回退和重复观测处理；
- `StatsSource` 接口；
- 一个读取 JSON 的模拟源；
- 一个只允许回环地址、使用非重置查询的 sing-box V2Ray Stats gRPC 数据源；
- 统计用户名到本地凭据 UUID 的受保护映射；
- 基于 Linux procfs 的核心进程重启身份。

模拟源只用于单元测试、集成测试和开发烟雾检查。正式适配器依据实际 VPS 审计结果实现，已经通过隔离回环试验和生产连续采集验证。任何新节点接入仍必须确认目标二进制包含 `with_v2ray_api`，不能假设参考项目中的配置或构建能力与目标服务器一致。

## 安全边界

- 采集器是唯一数据库写入者；查询 CLI 使用 SQLite 只读模式。
- 数据库允许保存 UUID，但数据库文件、WAL/SHM 和备份均按凭据文件保护。
- UUID 不进入普通查询输出、事件消息或服务日志。
- 参考项目源码不参与主项目构建。
- 不包含 Web 服务、网络监听、SSH 客户端或任意 shell 执行入口。
- VPS 只读审计与后续写入、安装、reload 是不同授权阶段。

## 测试夹具的作用

从真实接口结构整理出的脱敏固定夹具用于重复验证：

- 首次观测只建立基线；
- 正常观测记录累计计数器差值；
- 已确认核心重启后进入新的计数器纪元；
- 无法确认原因的计数器回退标记为缺口；
- 重复或过期观测不重复累计。

这些测试用于防止回归，但不替代真实 VPS 的只读兼容性检查。
